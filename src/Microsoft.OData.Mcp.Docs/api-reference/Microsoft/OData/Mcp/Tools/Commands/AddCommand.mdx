## Summary

Interactive wizard command that generates the `claude mcp add` registration line for a remote OData
service, including the outbound OAuth flags `odata-mcp start` needs to sign in.

## Remarks

This command provides an interactive experience for users to configure their OData
service connection and generates the appropriate `claude mcp add` command for Claude Code.
Tests must assign [Input](https://learn.microsoft.com/dotnet/api/microsoft.odata.mcp.tools.commands.addcommand.input) and [Output](https://learn.microsoft.com/dotnet/api/microsoft.odata.mcp.tools.commands.addcommand.output) instead of calling
[TextReader)](https://learn.microsoft.com/dotnet/api/system.console.setin(system.io.textreader)). Windows testhost wraps `SetIn` in
`SyncTextReader` and leaves [IsInputRedirected](https://learn.microsoft.com/dotnet/api/system.console.isinputredirected) false, so
[Boolean)](https://learn.microsoft.com/dotnet/api/system.console.readkey(system.boolean)) blocks the Visual Studio Test Explorer.

Per `specs/v3/AUTHENTICATION.md` "CLI UX → `odata-mcp add`" the generated command never
carries an access or refresh token, and never carries `--env`: `claude mcp add --env` takes
`KEY=VALUE`, so a bare name is either invalid or empty. A client secret is an instruction, not a
value. An API key, a Basic password, and a pasted bearer token do reach the configuration file, and each
one is warned about at the moment it is collected.
