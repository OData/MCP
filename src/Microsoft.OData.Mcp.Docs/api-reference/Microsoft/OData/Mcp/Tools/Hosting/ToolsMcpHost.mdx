## Summary

The local MCP host for a remote OData service: one generic host that owns the authenticating
`"OData"` client, the unauthenticated `"OAuth"` client, the token cache, the catalog built from
the service's `$metadata`, and — when the process is serving stdio — the MCP server itself.

## Remarks

There is exactly one `Build()`, and everything the process needs is registered before it. That
matters because [IHttpClientFactory](https://learn.microsoft.com/dotnet/api/system.net.http.ihttpclientfactory) cannot be shared between service providers: the
`$metadata` GET has to run through the same authenticating client the tools later run through, or
the credential the handler negotiated would be attached to one client and thrown away with the other.

## Examples

```csharp
using var lifetime = new CancellationTokenSource();
using var toolsHost = await ToolsMcpHost.CreateAsync(
    "https://api.example.com/odata",
    new OutboundOAuthOptions { ClientId = "cli" },
    includeStdioMcp: true,
    verbose: false,
    lifetime,
    lifetime.Token);

await toolsHost.Host.RunAsync(lifetime.Token);
```

#### Examples

```csharp
// A test can point both named clients at in-process servers without touching the network.
using var toolsHost = await ToolsMcpHost.CreateAsync(
    resource.ServiceRoot.ToString(),
    options,
    includeStdioMcp: false,
    verbose: false,
    lifetime: null,
    cancellationToken,
    services =&gt;
    {
        services.AddHttpClient(ODataMcpAuthConstants.ODataHttpClientName)
            .ConfigurePrimaryHttpMessageHandler(() =&gt; resource.Server.CreateHandler());
    });
```

#### Remarks

The order here is the whole point. Registrations first, *configureServices* last,
then one `Build()`; only afterwards does anything touch the network, because the
`$metadata` GET is what drives the authentication handler through discovery, consent, and the
token cache. A restart that finds a still-valid cached token spends exactly one request here: no
device code, no token endpoint, no discovery.

The credential store is not probed here either: `OutboundOAuthClient` proves it usable on the
first acquisition, so a service that answers `$metadata` without a challenge never touches the
operating system keyring and never creates a token cache directory.
