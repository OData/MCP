## Summary

The RFC 8414 authorization server metadata document, or its OpenID Connect discovery document
counterpart, restricted to the endpoints, advertised grants and scopes, and PKCE / dynamic client
registration capability flags outbound OAuth discovery actually reads.

## Remarks

Deserialized exclusively through [OutboundOAuthJsonContext](https://learn.microsoft.com/dotnet/api/microsoft.odata.mcp.authentication.outbound.outboundoauthjsoncontext); this type is never read with
reflection-based `System.Text.Json` serialization (AOT: JSON source-gen; no reflection). Unknown
fields the discovery document may carry (signing algorithms, UI locales, and similar) are intentionally
not modeled here per `specs/v3/AUTHENTICATION.md` "Authentication outbound" type map.

## Examples

```csharp
var json = await client.GetStringAsync(wellKnownUri);
var metadata = JsonSerializer.Deserialize(json, OutboundOAuthJsonContext.Default.AuthorizationServerMetadata);
if (metadata is not null &amp;&amp; metadata.AdvertisesGrant(ODataMcpAuthConstants.DeviceCodeGrantType))
{
    // Start a device code grant.
}
```

### <Icon icon="tag" iconType="duotone" color="#419AC5" size={24} className="mr-2" /> Issuer

Gets or sets the issuer identifier, exactly as the document spells it.

#### Syntax

```csharp
public string Issuer { get; set; }
```

#### Property Value

Type: `string?`

#### Remarks

Deliberately a [String](https://learn.microsoft.com/dotnet/api/system.string) rather than a [Uri](https://learn.microsoft.com/dotnet/api/system.uri). RFC 8414 section 2 and RFC 9207
both compare issuer identifiers by simple string comparison, and [Uri](https://learn.microsoft.com/dotnet/api/system.uri) normalizes: it
turns the authority-only issuer `https://accounts.google.com` into
`https://accounts.google.com/`, which would make a conforming authorization server's
`iss` look like a mix-up attack. Use [AuthorizationServerMetadata.IssuerUri](/api-reference/Microsoft/OData/Mcp/Authentication/Outbound/AuthorizationServerMetadata#issueruri) where a URI is genuinely needed.

## Methods

### <Icon icon="function" iconType="duotone" color="#419AC5" size={24} className="mr-2" /> AdvertisesGrant

Determines whether this server advertises a grant type, treating the RFC 8628 short form
`device_code` and the [ODataMcpAuthConstants.DeviceCodeGrantType](/api-reference/Microsoft/OData/Mcp/Authentication/Outbound/ODataMcpAuthConstants#devicecodegranttype) URN as
equivalent in either direction.

#### Syntax

```csharp
public bool AdvertisesGrant(string grantType)
```

#### Parameters

| Name | Type | Description |
|------|------|-------------|
| `grantType` | `string` | The grant type to look for, such as `authorization_code` or `device_code`. |

#### Returns

Type: `bool`
[`true`](https://learn.microsoft.com/dotnet/csharp/language-reference/builtin-types/bool) when [AuthorizationServerMetadata.GrantTypesSupported](/api-reference/Microsoft/OData/Mcp/Authentication/Outbound/AuthorizationServerMetadata#granttypessupported) contains an ordinal match for
*grantType*, or its device-code counterpart; otherwise [`false`](https://learn.microsoft.com/dotnet/csharp/language-reference/builtin-types/bool).

#### Exceptions

| Exception | Description |
|-----------|-------------|
| `ArgumentException` | Thrown when *grantType* is [`null`](https://learn.microsoft.com/dotnet/csharp/language-reference/keywords/null), empty, or whitespace. |

#### Remarks

Advertised grant lists use either spelling depending on the authorization server, so a caller that
asks for either one gets the same answer regardless of which spelling was actually published.
