## Summary

The outbound OAuth state machine: it owns one OData service root's cached token, decides whether that
token can still be attached, refreshes it exactly once when several callers race, and runs the advertised
grant when there is nothing left to refresh.

## Remarks

Nothing here ever logs an access token, a refresh token, a device code, an authorization code, or a PKCE
code verifier: every token that reaches a log goes through
[TokenContainer)](https://learn.microsoft.com/dotnet/api/microsoft.odata.mcp.authentication.outbound.outboundauthlogredactor.describetoken(modelcontextprotocol.authentication.tokencontainer)) first. There is
no background refresh — an idle process sends no token requests at all — because the send path checks
remaining lifetime against [ODataMcpAuthConstants.TokenRefreshSkew](/api-reference/Microsoft/OData/Mcp/Authentication/Outbound/ODataMcpAuthConstants#tokenrefreshskew) and a
`401 invalid_token` remains the fallback for a token whose lifetime the client cannot compute.

The credential store is proved usable inside
[CancellationToken)](https://learn.microsoft.com/dotnet/api/microsoft.odata.mcp.authentication.outbound.outboundoauthclient.acquireasync(system.collections.generic.ireadonlylist{system.string},system.int32,system.boolean,system.threading.cancellationtoken)) rather than at host
construction, and only when no explicit credential was configured, so a service that needs no sign-in at
all never touches the operating system keyring.

## Examples

```csharp
var client = new OutboundOAuthClient(
    new Uri("https://api.example.com/odata/"),
    httpClientFactory,
    options,
    tokenCache,
    discovery,
    loggerFactory);

var token = await client.GetValidTokenAsync(cancellationToken)
    ?? await client.AcquireAsync(challenges, 401, interactiveAllowed: true, cancellationToken);
```

### <Icon icon="function" iconType="duotone" color="#419AC5" size={24} className="mr-2" /> AcquireAsync

Runs discovery and the advertised grant to obtain a brand new token, and persists it.

#### Syntax

```csharp
public System.Threading.Tasks.Task<ModelContextProtocol.Authentication.TokenContainer> AcquireAsync(System.Collections.Generic.IReadOnlyList<string> wwwAuthenticate, int statusCode, bool interactiveAllowed, System.Threading.CancellationToken cancellationToken)
```

#### Parameters

| Name | Type | Description |
|------|------|-------------|
| `wwwAuthenticate` | `System.Collections.Generic.IReadOnlyList<string>` | The raw `WWW-Authenticate` header values the challenge arrived on. |
| `statusCode` | `int` | The HTTP status code the challenge arrived with. |
| `interactiveAllowed` | `bool` | Whether this process may run an interactive grant such as device code. |
| `cancellationToken` | `System.Threading.CancellationToken` | The token that cancels discovery and the grant. |

#### Returns

Type: `System.Threading.Tasks.Task<ModelContextProtocol.Authentication.TokenContainer>`
The acquired token, already written to the cache.

#### Exceptions

| Exception | Description |
|-----------|-------------|
| `ArgumentNullException` | Thrown when *wwwAuthenticate* is [`null`](https://learn.microsoft.com/dotnet/csharp/language-reference/keywords/null). |
| `InvalidOperationException` | Thrown when this host's credential store cannot round-trip a value. |
| `OutboundDiscoveryException` | Thrown when no authorization server can be discovered, when no client identifier is available, or
when the authorization server advertises no grant this build can run. |
| `OAuthConsentRequiredException` | Thrown when the selected grant needs a human and [OutboundOAuthOptions.ConsentPresenter](/api-reference/Microsoft/OData/Mcp/Authentication/Outbound/OutboundOAuthOptions#consentpresenter)
is [`null`](https://learn.microsoft.com/dotnet/csharp/language-reference/keywords/null). The grant stays pending so a caller that elicits the URL can finish it
with [CancellationToken)](https://learn.microsoft.com/dotnet/api/microsoft.odata.mcp.authentication.outbound.outboundoauthclient.completeinteractivegrantasync(system.threading.cancellationtoken)). |
| `OAuthTokenException` | Thrown when the grant fails, including when it outlives [OutboundOAuthOptions.AuthTimeout](/api-reference/Microsoft/OData/Mcp/Authentication/Outbound/OutboundOAuthOptions#authtimeout). |
| `NotSupportedException` | Thrown when the selected grant is not implemented in this build. |

#### Examples

```csharp
var challenges = response.Headers.WwwAuthenticate.Select(x =&gt; x.ToString()).ToList();

var token = await client.AcquireAsync(challenges, (int)response.StatusCode, interactiveAllowed: true, cancellationToken);
```

#### Remarks

The whole interactive wait runs under a linked cancellation source that fires after
[OutboundOAuthOptions.AuthTimeout](/api-reference/Microsoft/OData/Mcp/Authentication/Outbound/OutboundOAuthOptions#authtimeout), so a human who walks away cannot pin the send path
open forever; the caller's own cancellation still surfaces as
[OperationCanceledException](https://learn.microsoft.com/dotnet/api/system.operationcanceledexception) rather than a timeout. The client credentials grant takes
none of that path: it needs no human, so it neither starts a timeout nor consults a presenter.

When a presenter is configured and the wait fails for any reason — the presenter threw, the timeout
fired, the end user refused — the pending grant is cleared, so the next call starts a fresh one
instead of failing forever with "an interactive sign-in is already pending". The deliberate
[OAuthConsentRequiredException](/api-reference/Microsoft/OData/Mcp/Authentication/Outbound/OAuthConsentRequiredException) thrown when no presenter is configured is the one path
that keeps the pending state, because a caller that elicits the URL finishes that same grant later.

### <Icon icon="function" iconType="duotone" color="#419AC5" size={24} className="mr-2" /> ForceRefreshAsync

Refreshes the cached token even when its remaining lifetime says it is still good, for the
`401 invalid_token` path where the resource server disagrees with the token's own
`expires_in`.

#### Syntax

```csharp
public System.Threading.Tasks.Task<ModelContextProtocol.Authentication.TokenContainer> ForceRefreshAsync(System.Threading.CancellationToken cancellationToken)
```

#### Parameters

| Name | Type | Description |
|------|------|-------------|
| `cancellationToken` | `System.Threading.CancellationToken` | The token that cancels the refresh. |

#### Returns

Type: `System.Threading.Tasks.Task<ModelContextProtocol.Authentication.TokenContainer?>`
The refreshed token, or [`null`](https://learn.microsoft.com/dotnet/csharp/language-reference/keywords/null) when there is nothing cached to refresh or the
authorization server rejected the refresh token.

#### Examples

```csharp
if (challenge?.Error == ODataMcpAuthConstants.ErrorInvalidToken)
{
    var refreshed = await client.ForceRefreshAsync(cancellationToken);
}
```

#### Remarks

Coalesced through the same gate as the lifetime-driven refresh, so a burst of simultaneous
`invalid_token` answers costs one token POST rather than one per request. A client credentials
token has no refresh token to spend, so this returns [`null`](https://learn.microsoft.com/dotnet/csharp/language-reference/keywords/null) and the caller falls
through to a fresh grant.

### <Icon icon="function" iconType="duotone" color="#419AC5" size={24} className="mr-2" /> GetValidTokenAsync

Returns a token that can be attached to the next `"OData"` request, refreshing it first when its
remaining lifetime has fallen inside [ODataMcpAuthConstants.TokenRefreshSkew](/api-reference/Microsoft/OData/Mcp/Authentication/Outbound/ODataMcpAuthConstants#tokenrefreshskew).

#### Syntax

```csharp
public System.Threading.Tasks.Task<ModelContextProtocol.Authentication.TokenContainer> GetValidTokenAsync(System.Threading.CancellationToken cancellationToken)
```

#### Parameters

| Name | Type | Description |
|------|------|-------------|
| `cancellationToken` | `System.Threading.CancellationToken` | The token that cancels the cache read and any refresh it triggers. |

#### Returns

Type: `System.Threading.Tasks.Task<ModelContextProtocol.Authentication.TokenContainer?>`
The token to attach, or [`null`](https://learn.microsoft.com/dotnet/csharp/language-reference/keywords/null) when nothing is cached, nothing can be refreshed, or
the refresh failed — in which case the caller runs
[CancellationToken)](https://learn.microsoft.com/dotnet/api/microsoft.odata.mcp.authentication.outbound.outboundoauthclient.acquireasync(system.collections.generic.ireadonlylist{system.string},system.int32,system.boolean,system.threading.cancellationtoken)) off the resulting
challenge.

#### Examples

```csharp
var token = await client.GetValidTokenAsync(cancellationToken);
if (token is not null)
{
    request.Headers.Authorization = new AuthenticationHeaderValue("Bearer", token.AccessToken);
}
```

#### Remarks

A token whose `expires_in` the authorization server omitted is attached as-is: the client cannot
prove it has expired, and a `401 invalid_token` is a cheaper way to find out than throwing away
a token that may still have hours left.
