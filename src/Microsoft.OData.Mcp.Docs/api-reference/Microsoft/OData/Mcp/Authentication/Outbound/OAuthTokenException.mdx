## Summary

The single exception type an outbound token, device authorization, or polling request throws when the
authorization server answers with an RFC 6749 section 5.2 error payload, or when the request never
reached one.

## Remarks

Per `AUTH-12` no member of this type ever carries an access token, refresh token, device code, or
client secret: [OAuthTokenException.Error](/api-reference/Microsoft/OData/Mcp/Authentication/Outbound/OAuthTokenException#error) and [OAuthTokenException.ErrorDescription](/api-reference/Microsoft/OData/Mcp/Authentication/Outbound/OAuthTokenException#errordescription) are copied straight from the
server's error payload, and the composed [Message](https://learn.microsoft.com/dotnet/api/system.exception.message) repeats only those two values
and the HTTP status. RFC 8628 device code polling reuses this type for its `authorization_pending`,
`slow_down`, `expired_token`, and `access_denied` answers, which is why
[OAuthTokenException.Error](/api-reference/Microsoft/OData/Mcp/Authentication/Outbound/OAuthTokenException#error) is exposed as a value a caller can branch on rather than only formatted into the
message.

## Examples

```csharp
try
{
    var response = await tokenEndpointClient.PostAsync(tokenEndpoint, form, clientId, clientSecret, authMethod, cancellationToken);
}
catch (OAuthTokenException ex) when (ex.Error == ODataMcpAuthConstants.ErrorAuthorizationPending)
{
    // Keep polling.
}
```
