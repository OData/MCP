## Summary

The consent-request payload passed to [OutboundOAuthOptions.ConsentPresenter](/api-reference/Microsoft/OData/Mcp/Authentication/Outbound/OutboundOAuthOptions#consentpresenter), and carried by
[OAuthConsentRequiredException](/api-reference/Microsoft/OData/Mcp/Authentication/Outbound/OAuthConsentRequiredException), when interactive sign-in is required to complete an outbound
OAuth grant.

## Remarks

Per `AUTH-12` this type never carries a `device_code`, an access token, a refresh token, or a
PKCE `code_verifier` — only what a human or an MCP client needs to complete sign-in out of band.
Fields that must stay off this type (the pending grant's `device_code`, `interval`,
`code_verifier`, expected `state`, and live `HttpListener`) live instead on
`OutboundOAuthClient`'s internal pending-grant state.

Every URL on this type is server-controlled: it comes from an authorization server that a malicious
protected resource could have named. Because a consent URL is handed to `ShellExecute` by the stdio
presenter and to an MCP client as an elicitation URL, the constructor is the chokepoint that refuses any
scheme other than `https`, or `http` on a loopback host, before either can happen.

## Examples

```csharp
var request = new OutboundConsentRequest(
    OutboundGrantKind.DeviceCode,
    new Uri("https://login.microsoftonline.com/common/oauth2/v2.0/devicecode"),
    "Sign in to continue.",
    userCode: "ABCD-EFGH",
    verificationUri: new Uri("https://microsoft.com/devicelogin"));
```

```csharp
public OutboundConsentRequest(Microsoft.OData.Mcp.Authentication.Outbound.OutboundGrantKind kind, System.Uri url, string message, string userCode, System.Uri verificationUri, string elicitationId = null)
```

#### Parameters

| Name | Type | Description |
|------|------|-------------|
| `kind` | `Microsoft.OData.Mcp.Authentication.Outbound.OutboundGrantKind?` | The grant kind this consent request is completing. |
| `url` | `System.Uri` | The absolute URL to open to complete sign-in. |
| `message` | `string` | The human-readable message describing what to do. |
| `userCode` | `string?` | The short code a human types at *verificationUri*, or [`null`](https://learn.microsoft.com/dotnet/csharp/language-reference/keywords/null). |
| `verificationUri` | `System.Uri?` | The verification URI a human is directed to, or [`null`](https://learn.microsoft.com/dotnet/csharp/language-reference/keywords/null). |
| `elicitationId` | `string?` | The correlation identifier, or [`null`](https://learn.microsoft.com/dotnet/csharp/language-reference/keywords/null) to generate a new `D`-format GUID. |

#### Exceptions

| Exception | Description |
|-----------|-------------|
| `ArgumentNullException` | Thrown when *url* is [`null`](https://learn.microsoft.com/dotnet/csharp/language-reference/keywords/null). |
| `ArgumentException` | Thrown when *url* is not an absolute URI, when *message* is empty or
white space, or when *elicitationId* is non-[`null`](https://learn.microsoft.com/dotnet/csharp/language-reference/keywords/null) and empty or white space. |
| `OutboundDiscoveryException` | Thrown when *url* or *verificationUri* is neither an `https`
URI nor an `http` URI on a loopback host. |

#### Remarks

The scheme check runs on both URLs and it runs here rather than at each presenter, because there is
no presenter this instance is guaranteed to reach: it is also carried by
[OAuthConsentRequiredException](/api-reference/Microsoft/OData/Mcp/Authentication/Outbound/OAuthConsentRequiredException) to whatever host catches it.
