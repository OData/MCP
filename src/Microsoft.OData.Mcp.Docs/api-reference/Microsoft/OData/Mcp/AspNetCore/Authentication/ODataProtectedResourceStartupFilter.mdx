## Summary

Validates [ODataProtectedResourceOptions](/api-reference/Microsoft/OData/Mcp/AspNetCore/Authentication/ODataProtectedResourceOptions) at startup and prepends
[ODataProtectedResourceMiddleware](/api-reference/Microsoft/OData/Mcp/AspNetCore/Authentication/ODataProtectedResourceMiddleware) to the pipeline, no matter how the app wrote its own
`Configure` delegate.

## Remarks

Going in through an [IStartupFilter](https://learn.microsoft.com/dotnet/api/microsoft.aspnetcore.hosting.istartupfilter) is what makes the feature one line for an API author:
there is no `UseODataProtectedResource` to remember, and no way to accidentally place it after
`UseAuthentication`, where the metadata document would answer `401` and tell a client nothing.

Validation runs here rather than on the first request so a misconfigured API fails the host instead of
failing whichever client happens to arrive first.
