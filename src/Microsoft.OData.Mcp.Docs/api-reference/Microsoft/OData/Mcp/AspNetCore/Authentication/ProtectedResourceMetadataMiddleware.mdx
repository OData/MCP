## Summary

Publishes RFC 9728 protected resource metadata for the configured route bases, and rewrites the
`WWW-Authenticate` challenge on a `401` beneath one of those bases so a client is told
where that document lives.

## Remarks

[ProtectedResourceMetadataStartupFilter](/api-reference/Microsoft/OData/Mcp/AspNetCore/Authentication/ProtectedResourceMetadataStartupFilter) puts this at the very front of the pipeline, before
authentication and authorization, because a protected resource metadata document that answers `401`
is useless — a client that follows `resource_metadata` into a challenge has learned nothing. That
is the "Graph trap" in `specs/v3/AUTHENTICATION.md`, and the only defence against it is serving the
document anonymously.

The default route base is the application root. Explicit [ProtectedResourceMetadataOptions.Prefixes](/api-reference/Microsoft/OData/Mcp/AspNetCore/Authentication/ProtectedResourceMetadataOptions#prefixes)
entries are Endpoint Routing route bases, including an empty string.

## Examples

```csharp
GET /.well-known/oauth-protected-resource
200 application/json
{"resource":"https://api.contoso.com","authorization_servers":["https://login.contoso.com/v2.0"],"bearer_methods_supported":["header"]}
```
