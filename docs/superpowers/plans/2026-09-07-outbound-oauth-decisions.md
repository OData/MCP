## 2. Design and API decisions

| # | Decision | Why | Cost to reverse |
|---|----------|-----|-----------------|
| D1 | `ToolsMcpHost.CreateAsync(string serviceUrl, OutboundOAuthOptions options, bool includeStdioMcp, bool verbose, CancellationTokenSource? lifetime, CancellationToken cancellationToken, Action<IServiceCollection>? configureServices = null)`. `BuildStdioHost` and the old `(url, authToken, ct)` overload deleted. The plan and TESTING.md §8.3 disagreed on the signature; spec rev 9 now documents this one. | `verbose` and `lifetime` were already needed by the commands; a second overload would have been deleted minutes later (see D8). | One signature edit + call sites in Tools and the test fixtures. |
| D2 | `OutboundOAuthClient` **owns the service root** (ctor `Uri serviceRoot`). `AcquireAsync(IReadOnlyList<string> wwwAuthenticate, int statusCode, bool interactiveAllowed, ct)` does not take it; `ODataOutboundAuthHandler` no longer derives the root from request URIs. | One client per service; deriving the root per request was fragile and let a redirect change the identity. | One signature. |
| D3 | `OAuthDiscovery.DiscoverAsync(Uri serviceRoot, IReadOnlyList<string> wwwAuthenticate, int statusCode, Uri? authorizationServerOverride, Uri? resourceOverride, ct)` takes the two overrides rather than `OutboundOAuthOptions`. | Keeps the discovery layer independent of the CLI options type. | One call site in `OutboundOAuthClient`. |
| D4 | `OAuthDiscovery.PrmCandidates` returns an **ordered `IReadOnlyList<Uri>`**: `[resource_metadata]` when the challenge carries an absolute one, else `[origin/.well-known/oauth-protected-resource, origin/.well-known/oauth-protected-resource{path}]` (path form only when the service root has a path). `DiscoverAsync` tries them in order until the first non-null PRM. | RFC 9728 allows both forms; probing both costs one extra 404 at most. | Cheap, test-visible. |
| D5 | **RFC 8707 `resource` is sent only when the PRM published a `resource` or the operator passed `--resource`.** No origin fallback. `OAuthDiscoveryResult.Resource` is `Uri?`. | Spec rev 9 note 5; sending an unrequested `resource` breaks authorization servers that don't implement RFC 8707. | An AS that *requires* `resource` needs `--resource` on the command line. |
| D6 | **RFC 9207 `iss` is compared by ordinal string equality against the raw issuer string.** `AuthorizationServerMetadata.Issuer` became `string?` (raw); a `[JsonIgnore] Uri? IssuerUri` is the parsed form. **Public API change** in a preview package. | `Uri.AbsoluteUri` normalizes (adds a trailing slash to authority-only issuers), producing false rejections. | Consumers use `IssuerUri` where they need a `Uri`. |
| D7 | Consent, authorize, and redirect URLs must be `https` or loopback `http` before reaching `ShellExecute`/elicitation (`OutboundConsentRequest` and `OutboundDiscoveryHttp.EnsureDiscoveryUri` share the predicate). `--redirect-uri` must be loopback `http`. | Security: never launch or elicit a plaintext non-loopback URL. | A plaintext-`http` non-loopback AS is refused (intended). |
| D8 | Task 4a.2 did **not** add the plan's interim dual-client `CreateAsync` overload; commands kept the old call until 4b.6 unified the host. No placeholder throw for unimplemented grants in 4a — `GrantSelector` owns grant selection. | Less throwaway code. | None. |
| D9 | **Identity assertion configured but not advertised fails first.** When `--idp-url`/`--idp-token-endpoint` + an id-token source are set and the AS does not advertise `urn:ietf:params:oauth:grant-type:jwt-bearer`, `GrantSelector.Select` throws `OutboundDiscoveryException("Identity assertion is configured but {issuer} does not advertise …; pass --grant or fix --idp-url.")` instead of silently falling through to device code. | AUTH-8 fail-first. | An operator with a misconfigured IdP gets an error instead of a device-code prompt (recoverable). |
| D10 | **Dynamic client registration for `--grant client_credentials` requests `token_endpoint_auth_method: client_secret_post`** and persists the returned `client_secret`. If the AS returns `none`, fail with `OutboundDiscoveryException("Dynamic client registration did not return a client secret; pass --client-id and --client-secret.")`. | A public client cannot run the client-credentials grant. | None. |
| D11 | **Send path, spec row (c):** when `ForceRefreshAsync` fails on an `invalid_token` challenge (and the send did not already refresh), the handler falls into the acquire branch (presenter or `OAuthConsentRequiredException`) instead of returning the 401. | Spec table row (c). | One extra acquisition attempt in the failure case. |
| D12 | `LatchkeyTokenCache.VerifyPersistence` runs on **first acquisition** (`OutboundOAuthClient.EnsureCredentialStoreAsync`, before discovery/grant), not in `CreateAsync`. A `LatchkeyBackendUnavailableException` on a **read** (`GetTokenForSendAsync`) is treated as "no token" with a Warning; acquisition still fails first with the actionable message. | Unauthenticated services (Northwind) must never touch the credential store, and a broken keyring must not break them. | None. |
| D13 | `ODataOutboundAuthHandler.ReadChallenges` and `ODataExecuteResult.ReadWwwAuthenticate` use `Headers.TryGetValues("WWW-Authenticate")`, not the typed `AuthenticationHeaderValue` collection. | The typed collection silently drops challenges it cannot parse. | None. |
| D14 | `add` wizard, **Discover mode:** a bare-`Bearer` 401 with no discovery hints is the *expected* case. The wizard prompts for the authorization-server issuer URL, runs RFC 8414/OIDC discovery on it, asks for `--client-id` only when the AS advertises no `registration_endpoint`, and emits `--auth-server` in the generated command. No `--env` flag. | Most real APIs (including the user's) don't publish PRM. | Wizard UX only. |
| D15 | Wire DTOs (`DeviceAuthorizationResponse`, `TokenEndpointResponse`, `OAuthErrorPayload`) were created in Task 2.3 rather than 4b.1 because the source-generated `OutboundOAuthJsonContext` must reference them. The plan's duplicate `ClientCredentialsGrantType` constant was dropped (duplicated `GrantTypeClientCredentials`). | Build order; DRY. | None. |
| D16 | Latchkey backend map: Windows → `Dpapi`, macOS → `MacOSKeychain`, Linux → `SecretService`, `ForAll` → `File`. Never `Auto` on Windows. | Windows Credential Manager caps secrets at 2,560 bytes; JWT access tokens routinely exceed that. | None. |
| D17 | **In-process hosts serialize the discovered `IEdmModel` to CSDL** (`EdmModelAdapter.ToCsdlXml`) and store it as `ODataMcpSession.MetadataXml`, so `resources/read odata://{prefix}/$metadata` returns the real document instead of `""`. (2026-09-08) | An MCP client reading the metadata resource on an in-process host got an empty string. | One extra `CsdlWriter` pass per `Rebuild()`. |
| D18 | **`AddODataProtectedResource`** (AspNetCore package, `Authentication/` folder, spec rev 10): an `IStartupFilter` puts `ODataProtectedResourceMiddleware` at the front of the pipeline; it serves RFC 9728 PRM at both well-known forms anonymously and annotates existing `Bearer` 401s under OData prefixes with `resource_metadata` (and `scope`). No auth scheme, no MCP server required. (2026-09-08) | Most OData APIs answer a bare `Bearer` 401; this is the one-line serving side of the CLI's discovery. | Additive. |
| D19 | The published PRM `resource` **carries the route prefix** (`{scheme}://{host}{pathBase}/{prefix}`, no trailing slash), one document per prefix; the origin-form document describes the *first* discovered prefix. An API that turns this on asserts that path is the audience it validates. | RFC 8707 audience should name the service root, not the whole host; multi-prefix hosts need distinct audiences. | An API validating an origin-only audience must set its audience to the prefixed form (the test fixture's `ResourceUri` was aligned the same way). |
| D20 | Challenge annotation stops at the first `Bearer` that lacks `resource_metadata`; token68 credentials, other schemes, and unparsable headers are copied byte-for-byte; `OnStarting` never throws. `ScopesSupported` serializes as `[]` when empty (SDK type is non-nullable; the client treats empty as "not advertised"). | Never corrupt an app's own challenge; cosmetic wire difference only. | None. |
